# cms-portal

一个可见出口。同一层里的多个出口彼此并列，不互相嵌套。

## 在树中的位置

`cms-avatar-layer` 之后，`front=1` 的 `cms-back` 之前。来源是地图节点 `portal`。Task 023 在生命体和反应堆之后画传送门，再画近景。

## 运行库交给它的数据

Task 060 抽出的字段：

| 字段 | 含义 |
|---|---|
| `pn` | 出口名字，如 `out00` |
| `pt` | 类型 |
| `x` / `y` | 位置 |
| `tm` | 目标场景。`999999999` 表示没有地图跳转 |
| `tn` | 目标落点名字 |
| `script` | 脚本名。第一阶段为空 |

类型 0 是出生点，名字通常是 `sp`，只给运行库用来放人，不创建元素。第一阶段的场景跳转用类型 2：从当前场景的出口到目标场景的落点。

## 第一阶段

每张合成场景一个类型 2 的出口。场景 A 的出口指向场景 B 的落点，B 的出口指回 A。

人走到出口上之后，由地图运行库切换场景。这个元素只显示出口，并标出可走进的范围。

这是第一阶段唯一接输入的地图交互。NPC 对话、反应堆和座位见同目录下的 `cms-npc`、`cms-reactor`、`cms-seat`，第一阶段不放进树。

## 不做什么

- 不发送 `CHANGE_MAP`。旧封包不是运行时。
- 不画类型 0 的出生点。
- 不处理类型 9 的脚本出口和类型 6 的 `tp`。
