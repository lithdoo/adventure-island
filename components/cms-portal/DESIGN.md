# cms-portal

一个可见出口。同一层里的多个出口彼此并列，不互相嵌套。

## 在树中的位置

`cms-avatar-layer` 之后，`front=1` 的 `cms-back` 之前。来源是地图节点 `portal`。Task 023 在生命体和反应堆之后画传送门，再画近景。

## 运行库交给它的数据

这些都是单个值，写成属性。`data` 是空对象。画面不放进保留数据，按类型去 `MapHelper.img` 取。

| 字段 | 放在 | 含义 |
|---|---|---|
| `pn` | `attrs` | 出口名字，如 `out00` |
| `pt` | `attrs` | 类型，十进制字符串 |
| `x` / `y` | `attrs` | 位置 |
| `tm` | `attrs` | 目标场景。`999999999` 表示没有地图跳转 |
| `tn` | `attrs` | 目标落点名字 |
| `script` | `attrs` | 脚本名。第一阶段为空 |

节点上还能出现 `delay`、`onlyOnce`、`image`、`hRange`、`vRange`。非 0 的个数分别是 425、26、1、3、3。`f`、`hideTooltip`、`horizontalImpact` 在这批图里都是 0。这些值有则写成属性。它们怎么改画面或触发，函数还没对上。

游戏动画在 `MapHelper.img/portal/game`，只有 `pv`、`ph`、`psh` 三个目录。帧的 `origin` 对准 `x`、`y`。编辑器图标在 `portal/editor`，画布按文件顺序是 `sp`、`pi`、`pv`、`pc`、`pg`、`tp`、`ps`、`pgi`、`psi`、`pcs`、`ph`、`psh`、`pcj`。Task 023 的合成器用 `pt` 当这个顺序的下标来画编辑标记，那不是游戏画面。按这个顺序，下标 5 的名字是 `tp`，下标 6 是 `ps`。

全库类型个数：0 有 8916，1 有 3119，2 有 1962，3 有 1296，7 有 1439，8 有 628，9 有 516，6 有 219，10 有 206，其余类型不到 20。类型 0 的编辑器图标名是 `sp`，只给运行库用来放人，不创建元素。第一阶段的场景跳转用类型 2，画面用 `portal/game/pv`。`pt` 和 `ph`、`psh` 的对应还没从函数对上。

## 第一阶段

每张合成场景一个类型 2 的出口。场景 A 的出口指向场景 B 的落点，B 的出口指回 A。

人走到出口上之后，由地图运行库切换场景。这个元素把 `pv` 画在出口坐标上。没有 `hRange` / `vRange` 的出口，走进判定用的矩形还没从函数对上。

这是第一阶段唯一接输入的地图交互。NPC 对话、反应堆和座位见同目录下的 `cms-npc`、`cms-reactor`、`cms-seat`，第一阶段不放进树。

## 不做什么

- 不发送 `CHANGE_MAP`。旧封包不是运行时。
- 不画类型 0 的出生点，也不画 `portal/editor` 的编辑器图标。
- 第一阶段只挂类型 2。
